# Skyward recovery：K60 Pro 可写 PIN 解密版

这是 **recovery 分区镜像**，不通过 DSU 启动。不能把它交给 DSU 安装器，也不能当作 Arch／EvoX 的 system.img。

| 项目 | 内容 |
| --- | --- |
| 机型 | REDMI K60 Pro / socrates |
| 镜像 | `images/recovery.img` |
| 原始大小 | 104,857,600 字节（100 MiB） |
| SHA256 | `bd1c80633e266071f90299f61d2361185c8337e016ce787a0576cd9f6e5e5e57` |
| 编译源码 | `bb88bc785175590c07d57b89e1d98d573a70b8c0` |
| 打包来源 | 官方 Android 16 OTA OS3.0.304.0.WMKCNXM |
| 实测设备 | 机主确认的 303 底包移植系统；Android 17 框架，vendor 自报 304／Android 13／API 33 |

底包、框架版本、vendor 属性和 recovery 打包来源是不同层的证据，详见共同版本说明。不能把“Android 16 基线／Android 17 实测”理解为所有 16／17 组合都适用。

## 实机验证

该精确镜像已实刷 `recovery_a` 并原生启动，镜像、运行程序和设备配置摘要均匹配。已验证 PIN 可写 data 解密、触摸、Wi-Fi、Windows MTP 文件操作，以及共享和应用私有测试目录的生产代码压缩备份恢复。ext4/F2FS 格式化、挂载和 discard 在一次性 128 MiB loop 镜像上通过。

可写访问与自动 fsck 修复、KeyMint 升级分别配置。本机关闭后两项及元数据密钥自动删除；正常文件系统检查点、日志、GC 和用户文件写入仍会发生。

返回 HyperOS 后，应用 UID 可读取恢复的普通和硬链接文件；测试包及测试文件均已清理，原 recovery 已恢复，四个启动相关分区摘要与测试前一致。

尚未实测完整 OTA、真实用户数据全量恢复／清空、实际 UFS 安全擦除、跨格式化的加密策略重建及切槽。不能用专用目录／loop 测试代替这些结论。

## 安装前必须知道

镜像是 boot header v4、**不含 kernel 的 recovery ramdisk**；本文件不是可直接 `fastboot boot recovery.img` 的独立启动镜像。此前内存测试使用的是另制的临时容器，不在本包内。

本机只允许在硬件槽 a 上操作。刷写前先从当前设备保存 recovery_a，核对原始大小与 SHA256，并确保有可用的 fastboot 回退通道。本包不附当前设备的回退备份，不应把打包用的官方 recovery 当作原机备份。

在你已经单独决定实际刷写、确认设备为 socrates、当前槽为 a、BL 已解锁并备份完成的前提下，目标是 `recovery_a`；只用本包的 `images/recovery.img`。不要刷 recovery_b，不要切 b，也不需要刷 boot、init_boot、vendor_boot 或 vbmeta。本文不提供自动刷写器。
